## Findings

1. **Must fix: scratch archive omits a required gate evidence file.** `scripts/run-local-rehearsal.ts:157–166` archives `script`, but not `scripts/test-flow-reporting.py`. The latter is required by current `asset-flow.json.evidence_paths`. In the fresh scratch tree, the subsequent `git add -f -- ...cfg.evidence_paths` encounters a nonexistent path and exits before the signature/review preflight and funding. A pure committed-tree manifest check confirmed the missing file. Include that exact evidence path in the archive or construct the archive from the required source/evidence paths. Add a pure staging-completeness check. No gate waiver is needed or appropriate.

2. **Must fix: mined transaction readback omits intended target/native value.** `scripts/run-local-rehearsal.ts:85–94` records `tx.to` and `tx.value`, but only validates sender, nonce, calldata hash, receipt success, gas and price. A receipt with the intended sender/nonce/input but a different target or value would not be rejected by this function. Deployment dry-run validation at `:182` also omits `tx.to`/CREATE type checks. Pass the expected target and native value to `record`, compare them, and validate CREATE versus canonical CREATE2 destination against each prepared action. The constructed normal requests appear consistent; this is a missing fail-stop assertion, not evidence that a wrong transaction was sent.

3. **Execution-plan limitation: deployment receipt checks happen after the eight-action Forge call.** `scripts/run-local-rehearsal.ts:184–187` marks the entire deployment in flight, invokes unchanged `script/deploy.sh` with Forge `--slow`, then imports transaction hashes/receipts only after Forge returns. `docs/RELEASE-REHEARSAL.md:55` says each hash is journaled and reconciled before any next action. Forge sequential receipt waiting does not itself demonstrate the driver's target/value/code/state checks between deployments. Keep the unchanged wrapper and identify the Foundry checkpoint/receipt evidence used to enforce that promise, or state this driver limitation accurately before approval. Do not introduce a deployment bypass.
