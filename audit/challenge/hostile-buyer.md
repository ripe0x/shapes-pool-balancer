# Informed continuation: permanently frozen curated NFT after purchase

Target: repository `0f017843ec333f499809f751e19017be325448e3`, mainnet fork block `26382349` through `https://mainnet.gateway.tenderly.co`, Solidity 0.8.28/Cancun/via IR. This continuation used the frozen transfer mock and real deployed FWA, VRF service and Shapes on an ephemeral fork. It changed no production or existing test file and made no mainnet broadcast. Test: `audit/challenge/HostileBuyer.t.sol`.

## Demonstrated sequence and rights

The creator lists a mock ERC-721 that, after `freeze()`, rejects every transfer from a nonzero holder. It has no unfreeze method. A separate normal curated NFT and one 0.01 ETH Shape are also listed. The Balancer is funded with 2 ETH, configured, opened and check-pointed. The mock freezes **after listing**. A funded buyer contract buys one draw through the real FWA pool; the selected listing ID is asserted to be the frozen NFT. FWA settlement leaves that listing in status **6, DeliveryPending**, held by FWA, with zero owner proceeds. Balancer upkeep succeeds, marks the item `PENDING` (state 2), pays only the measured keeper reward from Balancer ETH, and restores status-0 admission using the remaining normal curated NFT and Shape.

After seven days plus one second, the named buyer contract calls FWA `refundFailedDelivery`. The listing becomes status **7, DeliveryRefunded**, still held by FWA. The buyer contract calls `withdrawAcquisitionRefund`; the returned amount equals the original FWA acquisition fee. Its actual ETH balance is **starting balance minus only the VRF service fee**, excluding gas paid by the test harness. This uses a funded contract buyer so the balances reflect real EVM value transfers; an initial EOA `vm.prank` attempt was unsuitable for payer-balance assertions because its balance did not move with the harness call. The creator's `recoverCuratedNFT` reverts with the mock's exact `Frozen()` error, and FWA remains owner of the frozen token. The buyer's refund is therefore **not blocked** by the same frozen ERC-721 transfer rule that blocks creator recovery.

A subsequent real purchase selects the listed Shape. The test asserts the acquisition's listing ID, the buyer contract's Shape ownership and positive FWA owner proceeds. Balancer upkeep collects those proceeds, mints/re-lists a replacement Shape and pays its keeper. Its liquid-ETH equality is asserted exactly: `after = before + ownerProceeds − 0.011 ETH mint cost − keeperReward`, with the pinned 0.01 ETH Shape and 0.001 ETH Shapes mint fee. `ownerProceeds` becomes zero, active Shape count returns to one, and admission remains status 0. Thus the frozen pending/refunded curated item did not block those particular later purchase/upkeep steps.

Finally, the creator closes, withdraws the **other** curated NFT, unwinds the active replacement Shape for exactly 0.01 ETH, and claims all remaining liquid ETH. The test asserts the creator received that full claim and Balancer ETH reached zero. The frozen token remains in FWA. These observations bound the loss to that NFT's custody in this mock/state; they do not imply it can be transferred or recovered while the collection keeps blocking it.

## Command and evidence limits

`FOUNDRY_TEST=audit/challenge forge test --match-path audit/challenge/HostileBuyer.t.sol --fork-url https://mainnet.gateway.tenderly.co --fork-block-number 26382349 -vv`: final run exited **0**, one test passed, zero failed, 32 files compiled with Solc 0.8.28, test gas 16,055,552. Two earlier focused runs failed: the first at a payer-balance assertion because the test used an EOA prank rather than a funded payer contract; the second reached FWA delivery status 4 because the test had not called `freeze()` before purchase. Both were harness errors corrected before the passing run. The final run adds explicit assertions for the drawn frozen listing, drawn Shape listing and Shape ownership.

This is a conditional result for one permanently transfer-blocking ERC-721, one buyer that requests its refund, one later Shape draw, and the pinned FWA/Shapes state. It does not establish whether a different collection can seize or burn the token, how long a live collection stays frozen, or whether every buyer exercises their seven-day refund right. A non-refunding purchaser can leave the NFT in FWA's delivery escrow; this test deliberately uses a refunding buyer. It does not prove broad safety of hostile NFT integrations or release readiness. Evidence is a local Foundry execution result, not a protected runner or human technical sign-off.
